# ✅ Чек-лист для тестирования Kimi интеграции

## 🎯 Основные тесты

### 1. Загрузка изображения анализа
- [ ] Загрузить PNG/JPG фото анализа крови
- [ ] Проверить консоль: "🤖 Запускаем Kimi для анализа..."
- [ ] Дождаться: "✅ Kimi завершил анализ на XXX символов"
- [ ] Проверить БД: в `user_analysis_photos` должно быть поле `description` с текстом
- [ ] Проверить поле `file_type`: должно быть "image"

### 2. Загрузка PDF документа
- [ ] Загрузить PDF анализа (например, протокол анализа)
- [ ] Проверить консоль: "📄 File type: PDF"
- [ ] Дождаться анализа (может быть медленнее чем изображения)
- [ ] Проверить БД: `file_type` должно быть "pdf", `description` заполнен

### 3. Использование кэша при повторном обращении
- [ ] Загрузить 2-й раз тот же анализ
- [ ] Проверить консоль: "📦 Используем предоставленное описание (кэш)"
- [ ] Убедиться что описание загружается мгновенно (из кэша БД)

### 4. Запрос в чат с анализами
- [ ] Убедиться что 2+ анализа загруженны и имеют описание
- [ ] Отправить сообщение в чат
- [ ] Проверить консоль: "🔄 Запускаем Kimi параллельно для анализов без описания..."
- [ ] Убедиться что ответ DeepSeek учитывает информацию из анализов
- [ ] Проверить что описания включены в контекст:
   ```
   ✓ Загруженные анализы и их описания:
     📊 Анализ крови: 1 файл(ов)
        Файл 1: Анализ крови показывает РОЭ 15...
   ```

### 5. Параллельная обработка Kimi + DeepSeek
- [ ] Загрузить анализ БЕЗ описания (очистить БД)
- [ ] Отправить сообщение в чат сразу же
- [ ] Проверить что:
   - Kimi начинает анализ параллельно
   - DeepSeek не ждёт результата Kimi
   - Ответ всё равно содержит информацию из анализа

### 6. Обработка ошибок Kimi
- [ ] Проверить что при ошибке Kimi:
   - Система продолжает работать
   - В `description` сохраняется сообщение об ошибке
   - DeepSeek всё равно генерирует ответ

## 🗄️ Проверка БД

### Таблица `user_analysis_photos`

```sql
SELECT id, analysis_group, file_type, description, created_at 
FROM user_analysis_photos 
ORDER BY created_at DESC 
LIMIT 5;
```

Ожидаемое содержимое:
- `file_type`: 'image' или 'pdf' ✅
- `description`: полный текст анализа (200+ символов) ✅
- `created_at`: свежие записи ✅

### Проверка кэширования

```sql
-- Две загрузки одного файла должны иметь ОДИНАКОВОЕ description
SELECT photo_name, description, upload_date 
FROM user_analysis_photos 
WHERE analysis_group = 'Анализ крови'
ORDER BY upload_date DESC 
LIMIT 5;
```

## 🚨 Возможные проблемы и решения

| Проблема | Симптом | Решение |
|---------|--------|---------|
| Kimi не отвечает | "❌ Kimi API error: 401" | Проверить KIMI_API_KEY в .env |
| Описание не сохраняется | `description` пусто в БД | Проверить permissions Supabase |
| file_type не сохраняется | NULL в БД | Убедиться что колонка есть в user_analysis_photos |
| Параллельность не работает | Ответ приходит после Kimi | Проверить что await находится в нужном месте |
| Описание очень короткое | < 100 символов | Увеличить max_tokens в kimiClient.js |

## ✨ Ожидаемые результаты

✅ При чате: Kimi работает параллельно, не блокирует ответ  
✅ Описания включены в контекст DeepSeek
